## A caller timeout does not expire shared voice discovery (2026-09-12 00:06, issue #91)

The first integration pass passed 2,022 tests and typecheck, but two
controlled transport probes still found cache bugs before the beta was
installed. Both use the actual Fish provider bundled for Node and an
injected fetch, with no live key or account.

- The own list answered immediately, while the first public request never
  settled. A 20 ms caller bound returned Default; after the fake transport
  recovered, a second listing still returned Default without another
  public request (`publicCalls: 1`, `cacheHits: 2`, `loads: 2`). The
  unresolved promise stayed in the shared slot forever. A timeout must
  expire the shared operation too, clear its in-flight slot, prevent late
  pagination/retries and generation-stale publication, and allow retry.
  The same rule applies to pending pasted-ID metadata requests.
- A successful public list was cached, then its explicit refresh failed
  with a network error. The refreshing provider reported a stale notice,
  but a new provider sharing that cache reported `[]`. The real browser
  rebuilds its provider when it reloads, so a per-instance notice vanished
  immediately. Refresh failure state must travel with the cached snapshot
  until a successful refresh clears it.

The cache counters are exposed inside the plugin sandbox by
`diagnostics.fishVoices()` (`cacheHits`, `loads`, `cachedAccounts`), so live
verification can prove reuse without relying on timing or returning keys.
The independent review also identified the budget boundary before starting
pasted-ID requests; a spent deadline must not start more network work.

## The public discovery window does not fit eleven seconds when fetched sequentially (2026-09-12 00:08, issue #91)

An uncredentialed Node fetch probe of public pages 1 through 10, with
`page_size=100`, returned exactly 1,000 items in 32,025 ms. Per-page times
were 3,156 / 3,246 / 3,170 / 3,334 / 3,168 / 3,180 / 3,310 / 3,166 /
3,154 / 3,141 ms. Sequential pagination would therefore reproduce the
empty-field symptom at the provider's eleven-second listing deadline on
this connection. Fetching the remaining known window concurrently after
its first page avoids making every round trip part of the critical path;
the platform's 1,000-result cap bounds that fan-out. The catalog's existing
fifteen-second outer bound remains unchanged.

## Explicit regional picks must not reuse a generic remembered voice (2026-09-12 02:46, issue #91)

The owner reported English (United States) and other regional choices
snapping back to English in PDF and EPUB. The current UI was committed
first as `70b3840`. Native Zotero 10.0.2-beta.9 was read from the installed
omni.ja: reader.js `setLanguage` at 82328, `_findFallbackVoice` at
82460–82502, and the popup language value at 38644–38647.

Generic voices count as regional candidates, and `regionChanged` requires
both requested and persisted regions to be nonempty. A remembered generic
voice therefore wins over an explicit region. The popup displays the
selected voice's region, so it shows English again. This is related to
#49's stale-language-entry fix, but that pass did not mix generic and
regional voices. Fish's stable IDs are not the cause.

The existing explicit-pick staging now selects an exact normalized variant
when the native remembered choice would retain the wrong one and the native
target-tier pool offers a match. It keeps matching remembered voices and
native already-working region changes, does not cross tiers to invent an
exact match, and leaves automatic restores and missing variants alone.
Generic English can be selected again when offered. Staging is cloned into
the reader as before; the global pref is written only by the native pick.

A second boundary is the native early return: `_region` can already say US
while the selected voice is generic, or be null after restoring a regional
voice. For an explicit available variant, the old requested-region field
is first aligned with the voice the popup actually displays, so the native
setter does not mistake the user's change for a no-op. The test fake now
models that early return. Seven regressions cover both memory-switch states,
round trips, stale fields, a matching remembered voice, native fallback and
automatic restores; they failed on the old behavior, then all 117 targeted
memory tests and typecheck passed. PDF/EPUB live verification follows.

## Expanded player opening needs an early visibility gate (2026-09-12 16:36, issue #81)

The installed Zotero reader bundle still initializes `ReadAloudPopup` with
`useState(false)` at `resource/reader/reader.js:38513`. Options toggles that
local state at :38611; it is not a manager preference. Native quota errors
also expand the panel at :38547-38551 and retain that behavior.
`chrome/content/zotero/xpcom/reader.js:267` obtains the remote interface
before constructing the reader UI, so `buildReaderInterface` is the early
attachment point. Existing-reader startup and `watchReader` are backstops,
not substitutes for that early attachment.

`player-expanded.ts` observes each reader document and uses the existing
Options button selector. Its stylesheet hides only a popup without the
ready marker. The first automatic click starts a bounded wait for the
`expanded` class; the marker releases visibility after that commit and
survives manual folding. New popup elements initialize independently.
Existing popups are adopted unchanged, including at a setting change.
Missing buttons, click failures, and noncommitting clicks reveal the ordinary
player and report errors. A document-access failure releases the entire
stylesheet gate. Reader-close hooks and shutdown disconnect observers,
cancel timers, and remove the stylesheet and marker.

The opt-in preference is `readAloud.openExpanded`, default false. The
ordinary settings path carries it through backup and sync. Diagnostics
report attachment, readiness, expansion, click dispatch, pending timeout,
and outcome. A final expanded diagnostic is not evidence of the first
visible frame; the new live checklist states that distinction explicitly.

The first complete automated pass passed 2,074 tests across 107 files;
the focused settings and controller checks and typecheck also passed.
The beta is `1.12.3-beta`, with `package.json` left at the released version.
Live verification remains pending: the delegated preflight found no
`mcp__zotero-dev__*` tools in this session, so it could not ping or identify
the installed build. No Zotero state was changed and no live test script
or successful live result is claimed. Section 3e records the remaining
