## A caller timeout does not expire shared voice discovery (2026-09-12 00:06, issue #91)

The first integration pass passed 2,022 tests and typecheck, but two
controlled transport probes still found cache bugs before the beta was
installed. Both use the actual Fish provider bundled for Node and an
injected fetch, with no live key or account.

- The own list answered immediately, while the first public request never
  settled. A 20 ms caller bound returned Default; after the fake transport
  recovered, a second listing still returned Default without another
  public request (`publicCalls: 1`, `cacheHits: 2`, `loads: 2`). The
  unresolved promise stayed in the shared slot forever. A timeout must
  expire the shared operation too, clear its in-flight slot, prevent late
  pagination/retries and generation-stale publication, and allow retry.
  The same rule applies to pending pasted-ID metadata requests.
- A successful public list was cached, then its explicit refresh failed
  with a network error. The refreshing provider reported a stale notice,
  but a new provider sharing that cache reported `[]`. The real browser
  rebuilds its provider when it reloads, so a per-instance notice vanished
  immediately. Refresh failure state must travel with the cached snapshot
  until a successful refresh clears it.

The cache counters are exposed inside the plugin sandbox by
`diagnostics.fishVoices()` (`cacheHits`, `loads`, `cachedAccounts`), so live
verification can prove reuse without relying on timing or returning keys.
The independent review also identified the budget boundary before starting
pasted-ID requests; a spent deadline must not start more network work.

## The public discovery window does not fit eleven seconds when fetched sequentially (2026-09-12 00:08, issue #91)

An uncredentialed Node fetch probe of public pages 1 through 10, with
`page_size=100`, returned exactly 1,000 items in 32,025 ms. Per-page times
were 3,156 / 3,246 / 3,170 / 3,334 / 3,168 / 3,180 / 3,310 / 3,166 /
3,154 / 3,141 ms. Sequential pagination would therefore reproduce the
empty-field symptom at the provider's eleven-second listing deadline on
this connection. Fetching the remaining known window concurrently after
its first page avoids making every round trip part of the critical path;
the platform's 1,000-result cap bounds that fan-out. The catalog's existing
fifteen-second outer bound remains unchanged.

## Three independent Fish sources replace automatic community discovery (2026-09-12 00:58, issue #91)

The owner narrowed the scope to official voices, the account's own voices,
and manual Model IDs, with an independent switch for each. The Model IDs
field's `?` points to `https://fish.audio/app/discovery/`. The unshipped
in-plugin search controller, its strings, and sample coordination were
removed. `fish.includeOfficial`, `fish.includeOwn`, and
`fish.includeManual` default true; an absent preference on an older
profile also means true. They are regular settings for backup and sync.

Fish Official is author `d8b0991f96b44e489422ca2ddf0bd31d`: an exact 338
unique, trained TTS models over four pages (100/100/100/38), none marked
taken down, ten tagged `zh`. `licensed=true` returns only seven Japanese
voices and is not an official-author filter. The provider queries the
stable author ID, not the nickname. Disabled sources neither load nor
contribute cached entries/notices. Any enabled source can retain a shared
ID; the union deduplicates by raw model ID. Default is independent of the
three switches and remains when all are off.

The controls are unbound and outside the provider's locked input block,
so source switches work while Fish is enabled, through the reading guard.
The Model IDs input retains its old `fish.voices` key and link compatibility;
turning Manual off keeps the text. The browser and its diagnostics carry
stale/limited notices beside usable voices. Shared loads have their own
injected AbortController, an operation deadline, generation checks and
persistent refresh-error state; consumer cancellation does not cancel a
load another reader is using.

The final review found one remaining budget bug: an expired official
refresh discarded already-cached manual metadata before checking that
cache. A failing test reproduced Default alone; moving the cache lookup
before the network deadline check kept the manual voice and still refused
to start an uncached ID lookup after the deadline. Fish/factory tests passed
77/77 with this fix, shipped to testing as `1.12.2-beta2`.

The first live pass on beta1 confirmed all eight source combinations,
338 official voices plus Default, no duplicate IDs, the retained existing
manual voice, and a full cloud count of 340. Repeated listing kept `loads`
at 3 while `cacheHits` rose 43 to 46. The three source controls were
editable with Fish enabled, the ID field was locked as expected, the
help contained the discovery URL, no community search panel remained,
and localization reported no blank/questionless entries. The source and
refresh guards canceled without changing the protected paused reader;
the one free-model connection probe reported 340 voices and successful
synthesis. Beta2's final pass and the remaining debug/auto-upload restoration
are recorded below when completed.
