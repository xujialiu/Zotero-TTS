## Player voice changes share preparation and paused resume (2026-09-15 00:15, issue #108)

The player and the shortcut previously had different transitions. Native
`selectVoice`, `selectTier` and persistent `setLanguage` resolve and apply
the new voice synchronously (`resource/reader/reader.js:82328–82364` in the
installed Zotero bundle). `_applyVoice` recreates the controller at the
current segment (`82507–82535`); native `play` unpauses that controller
(`82558–82568`). The shortcut's separate prepared handoff bypassed that
restart, but its paused branch selected immediately without fetching.

`voice-switch.ts` now attaches to those three manager operations. A
synchronous preview runs native choice resolution and the memory layer's
locale staging while `_applyVoice`, persistence and state notifications are
suppressed. The choice fields are restored before returning to the caller.
The memory layer excludes previews from its pick observer. At handoff the
resolved fields are applied and the native selection adopts the prepared
controller; the native selection still owns persistence and shared-voice
propagation. Picking the original voice cancels without recreating it, but
still passes through the native pick so an unchanged preference can be
learned by memory-sync's existing observer.

Pause keeps preparation alive and disarms any scheduled old-source stop.
The old controller and its offset remain the resume fallback. A prepared
resume uses a single identifiable paused word and the next word's actual
target timestamp. A grouped timestamp cannot identify that paused word:
the original voice finishes the sentence instead. With target audio still
pending, native playback resumes first and the usual prepared handoff
follows. A suspended target AudioContext can decode while paused; its
output is resumed only after Play. Skip, speed, stop, close and disposal
invalidate pending work, including delayed output startup.

Native `_getAudioData` retains in-flight promises and `destroy` clears its
maps without an abort API (`40329–40406`). Destroying a prepared controller
alone therefore did not cancel synthesis. Each pending switch now owns an
injected AbortController, and the composite interface captures its signal
by requested voice ID. Preparation requests deduplicate within that
signal, separately from ordinary playback, so cancelling one cannot stop
another caller. Cancelled results are not cached and preparation does not
launch the plugin's ahead-of-playback warmer. Zotero's official remote
interface exposes no request cancellation: its late result is discarded,
but no claim is made that an already submitted official request is stopped
or its quota returned.

The first paused-preparation regression failed with no requested segment.
The paused-resume and grouped-timestamp regressions independently reproduced
the old-voice resume and unsafe grouped-word jump. The initial full suite
passed 2,334 tests; the final original-voice re-pick check and correction
passed the 34-test handoff suite, typecheck and build. The live run uses
`1.12.10-beta`; its results belong on #108, with executed methods retained
in the voice-switch kit. Automated results do not establish listening
continuity or real-provider timestamp accuracy.

## Native resume and notification cleanup pass in beta2 (2026-09-15 11:09, issue #108)

The tester's first run exhausted its usage allowance. The main session
recovered the disk results and confirmed restoration before continuing.
The initial suspended-context observations were not proof of an absent
audio device: document user activation and bounded `AudioContext.resume()`
enabled both native clocks. The final fixture uses `sentence` granularity,
and a Premium GB voice makes the GB-to-Premium expectation valid. The
real-provider probe must pass `voice.impl`, not the voice wrapper whose
prototype getters can be hidden across compartments. Its optional warmer
is disabled so an unrelated prefetch cannot become the cancellation probe.

PDF and EPUB both resumed prepared audio in the same segment at char 7,
target offsets 0.700 and 0.830 seconds, without first playing the old voice.
Locale and tier changes then committed at word boundaries. A delayed
target let the original voice resume first; missing or grouped word
timings finished the original sentence and adopted the next at offset 0.
The actual Kokoro response contained 47,660 bytes and five timestamps;
the controlled fetch probe separately observed an aborted synthesis signal
and successful independent subsequent request. The issue holds the tables.

Final error review found a preexisting toast hide callback running after
its reader document died. Manual voice notices now exercise that lifetime
more often. A narrow catch ignores only the dead-object error; another
regression preserves unrelated error reporting. The beta2 live cleanup
closed an EPUB with its notice still visible, waited 5.5 seconds, and
observed no new dead-object console error. All fixture readers/items,
transport hooks and named prefs/user flags were restored; owner readers
kept their paused position and speed. The final suite passed 2,337 tests,
typecheck and build. No subjective listening assessment is claimed.
