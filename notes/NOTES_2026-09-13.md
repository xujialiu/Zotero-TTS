## Multiple bracketed phrases cross the single-pair boundary (2026-09-13 01:47, issue #96)

A local execution of `prepareSpeechText` confirmed that
`<Log in> <Register> <Play as guest>` becomes
`Log in> <Register> <Play as guest`: only positions 0 and 34 are removed.
The first-opening/last-closing rule in `src/core/speech-text.ts` treats
separate phrases as one enclosing pair. `<A><B>` likewise becomes `A><B`.
The existing tests cover nested and unmatched brackets, but not sibling pairs.

The offset restoration helper already accepts an ordered list of removed
positions; any broader removal rule must retain that ordering and verify
word ranges across each deletion, including cached results. The original
document must keep its coordinates. Research used the existing helper
transpiled in memory, without production edits or a Zotero bridge run;
live segmentation and audible behavior remain unverified. The owner has
requested a recommendation before implementation.

## Sibling wrappers retain ordered source offsets (2026-09-13 01:57, issue #96)

Speech preparation now scans bracket depth and records only each group's
outer opening and closing positions. All groups must be separated and
surrounded by punctuation, symbols or whitespace; ordinary outside text
or an unmatched closing bracket rejects the entire transformation. Nested
groups lose one outer layer, never every bracket recursively. The old
single-wrapper `<a < b>` case is retained when there is exactly one closing
bracket and no subsequent opening bracket; ambiguous multi-group imbalance
is left unchanged rather than guessing which operator was punctuation.

The deleted-position array remains ordered, so `restoreSpeechOffsets`
needs no new mapping rule. Tests exercise all six original words of the
reported example through plugin and native interfaces, repeat plugin
requests through the cache, and reuse that cache for the plain text.
Adjacent removed characters and UTF-16 surrogate pairs also map correctly.
Multiple empty groups use the existing silence path; prefetch prepares
multiple groups using the same helper. The diagnostic now reports the
actual number of removed pairs.

The test build is 1.12.5-beta4, selected after checking the other worktree's
1.12.5-beta3. The owner deferred bridge use, so it has not been installed
or verified live. Section 3g item 8 and `limitations.md` retain the pending
checks; the older #94 run is not reused as evidence for this change.
