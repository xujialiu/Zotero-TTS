## The PDF can move before its scroll event arrives, so instant scrolling still drops the follow lock (2026-09-11 14:18, issue #85)

The owner's no-input follow-stop report prompted another bridge run on
Zotero-TTS 1.12.0 and Zotero 10.0.2-beta.9+c77df79af (BuildID
20260909034856). The issue comment holds the trials and measurements;
these are the conclusions that change the earlier investigation.

- **A moved viewport does not imply a delivered scroll event.** In two
  paused-view follow trials, the #83 target was correct and `scrollTop`
  had reached it before navigation returned. The native scroll event
  arrived about two seconds later, after the flag had cleared, and the
  native listener unlocked. Instant scrolling failed too. The instant
  trial began and ended minimized; smooth's initial window state was not
  sampled. The old instant-success observation is specific to its trial,
  not a general remedy for #85.
- **Every push owns a timer but all timers clear one flag.** Installed
  `resource/reader/reader.js:31516–31530` arms each debounce immediately;
  `76469–76487` clears the shared flag on each completion. An old
  completion cleared a newer push's flag after 12 ms, another after
  26 ms, even with no scroll. This establishes shortened protection,
  not a separate natural lock-loss reproduction. The late-event path is
  `75412–75419` to `_onManualNavigation` at `76776–76779`.
- **Word timers are not an audio clock.** The from-start attempt stayed
  on segment 0 for 136 seconds: decoded audio, buffering false, but
  AudioContext suspended and currentTime zero. Its word timers still
  advanced (`39944`, `40019–40048`, `40087–40101`). A bounded resume
  timed out; the device/autoplay cause remained unknown. The owner's
  exact uninterrupted-playback failure was not reproduced.
- **Opening Read Aloud can revive a hidden reader itself.** Chrome's
  `xpcom/reader.js:2155–2169` keeps the selected or playing tab's docShell
  active; the reader's suspend/resume paths then restore its PDF pages.
  Initial hidden state and zero rendered pages do not by themselves
  prevent a background investigation. The main window and nested reader
  documents can report different visibility states.
- **Restoration is observable.** All 21 listeners and seven descriptor
  overrides were removed. Original native, persisted, and plugin
  bookmarks were restored through the inspected Item API and the live
  sampler, without editing storage files; restoration updates write
  timestamps even when the positions match. Voice/memory preferences
  stayed byte-identical, and the player returned to closed and inactive.

No implementation was changed. The controlled failure belongs to #85;
#83's correct target and successful scroll were verified, while the
owner's natural failure point remains open.

## The plugin owns PDF follow intent while Zotero keeps the state and highlight work (2026-09-11 15:25, issue #90)

The owner approved a PDF-only follower rather than another timing patch
for #85. `pdf-follow.ts` keeps per-view intent, latest-state recovery and
input listeners; `sentence-in-view.ts` retains #83's geometry. The issue
holds the plan, review corrections and verification results.

- **One owner, not periodic relocking.** A reversible instance accessor
  makes the native `_readAloudPositionLocked` read false. The installed
  `setReadAloudState` is async but has no await: it renders synchronously,
  then would schedule the native follow (`reader.js:76421–76490`). Its
  original arguments, state/segments identity and return value are kept;
  the plugin follows after that synchronous work. Native scroll listeners
  keep their other popup/selection effects but cannot change plugin intent.
  Old queued follow-shaped navigations are discarded on owned views.
- **The failure is persistent.** A second research run got real audio
  advancement through a trusted Shift+Space. After one native unlock,
  197 further state pushes produced no navigation while multiple later
  sentences played at unchanged scrollTop. Window restoration preceded
  the unlock by 46 ms, so the owner's complete no-input sequence remains
  unproven. Stable minimized playback instead produced 432 navigation
  calls without physical movement; the new controller defers hidden
  scrolling and remeasures the latest state on return, only while following.
- **Manual input is not a scroll event.** Meaningful wheel, scrollbar,
  hand/touch pan and explicit location/page/history/find navigation stop
  following. Zoom and ordinary clicks do not. Cancel an outstanding
  animation at its current offsets before letting manual navigation win.
- **Keyboard order is part of correctness.** Existing shortcuts and native
  selection handling run at window capture. PDF.js Home/End and page-fit
  PageUp/PageDown run at window bubble and prevent default. Detect page
  keys at document capture, between them; accept the PDF body's own target
  but not editable controls. Selection keys consumed at window capture use
  `_scrollSelectionHeadIntoView(selectionRanges)` instead: its six callers
  are all keyboard selection/annotation-boundary changes, not ordinary
  clicks or Read Aloud. Walk those reader-realm ranges by index.
- **Not every play button calls the explicit view lock.** Preserve native
  paused-to-playing recovery when the current sentence is still in view
  (`76431–76432`), without accepting arbitrary native lock writes. Gray-area
  touch panning is also allowed with an annotation tool (`77814–77824`);
  checking only the pointer tool misses it.
- **Undo in reverse order.** Highlight styling wraps the same state method
  before the follower. Shutdown must restore follow before highlight or
  it resurrects the removed highlight wrapper. Per-view destroy/dispose
  also removes host-window listeners, find callbacks and scheduled frames;
  a dead view must not leave listeners in its still-live host window.
- **A diagnostic's old target is not a new scroll.** The first beta's live
  installation proved ownership but showed the previous release's `last`
  record while hidden. Ownership acquisition/release now clears it; only
  a decision made by this controller can populate it. Native lock false is
  intentional: inspect `owned`, `following` and `pending` instead.

## An active PDF can be renderable while the host chrome document still reports hidden (2026-09-11 15:39, issue #90)

The beta2 live run exposed an overly broad eligibility gate: the PDF's
`document.hidden` was false and its view was not suspended, with the main
window maximized and its widget visible, but the host chrome document
still reported hidden. Real audio advanced through 21 segments and
following stayed true, yet the host-document check deferred every scroll.
Focus and a restore cycle did not change that flag. The issue comment
records the measurements, not an assertion that OS-visible motion passed.

Use the PDF document's hidden state, view suspension and host minimization
for scroll eligibility. Keep observing host visibility/focus/resize as
recovery signals, but do not treat its independent hidden flag as proof
that the PDF cannot scroll. Beta3 preserves hidden/minimized deferral and
remeasures the latest sentence on recovery; an already disengaged view
stays disengaged. The regression test models different host/PDF document
states, rather than giving both one fake document.

## Beta3 keeps follow intent through late native events and yields to trusted manual navigation (2026-09-11 16:06, issue #90)

The final bridge pass used 1.12.1-beta3, bundle SHA-256
`d7e258e0f05127a3ffc0dc9c27027b966d1afeb3f0643c7d2fc1900c51bd77be`.
The issue and §3d hold the complete verification table and limits.

- **The two directions are distinct.** A no-input 95-second run reached
  segment 35 with following still on and 28 distinct targets. Native
  manual-navigation calls, false lock writes and a delayed scroll did
  not disengage it over later real segments 35–43. Trusted PageDown
  did disengage it, and real segments 43–50 produced no new target.
- **The body/key and input routes work live.** Trusted End physically
  moved 1237→9568. Shift+Enter and sentence/paragraph skip reengaged;
  direct manager play with the sentence in view produced reason
  `resume`. A trusted click and Ctrl+wheel zoom kept following; an
  ordinary trusted wheel stopped it. Actual find-result and Next Page
  navigation stopped it too. This did not establish scrollbar/gesture
  behavior or priority in the middle of a moving animation.
- **A hidden chrome document is not the whole rendering story.** The
  first natural run attempted targets but never physically moved; a
  direct native smooth control likewise stayed at 0, while positional
  scrolling reached 600 and rAF ran. Later, paused restoration really
  moved 9568→6002→5660→5648 toward the latest segment 53 target 5648.86,
  replacing the old 4583.66 target. Do not collapse these observations
  into either "all scrolling passed" or "no frame ever ran".
- **Input construction is a compartment operation.** TIP succeeded with
  KeyboardEvent dictionaries cloned into the PDF window and explicit
  Shift keydown/keyup. The un-cloned dictionary produced an empty key;
  that is a probe error, not a shortcut defect. Consumption alone is
  not proof: also record trusted target, segment and follow state.
- **Readiness and asynchronous restoration matter.** The secondary's
  viewerContainer was not ready at its first sample. Once ready, a
  controlled native state push installed ownership with zero rendered
  pages, and split closure removed it. Automatic first readiness remains
  unit-covered, not a live pass. Find restoration also needed a second
  supported update after an outstanding result callback repopulated the
  cleared result; final full JSON matched the original.
- **Error baselines are not interchangeable.** Beta2 added one source-less
  dead-object record at 1789111772510 even though its bounded debug text
  contained none. Beta3 added no dead-object and no plugin debug failure;
  four source-less undefined exceptions in the installation window remain
  unattributed. Neither result licenses claiming an empty error console.
- **Cleanup was complete.** Eighteen listeners, all test timers and the
  root were removed. Native/persisted/plugin bookmarks were restored
  (timestamps updated), with 58 rows and no pending writer. Voice/memory
  preferences, zoom, full find state and split state were restored;
  later external minimization was respected. Beta3 remains installed,
  with the player closed. The implementation is not committed or released;
  continuous visible motion and the remaining manual checks await the
  owner's feedback.
