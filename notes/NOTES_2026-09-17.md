## Floating menus use the host viewport and keep the player stationary (2026-09-17 00:31, issue #118)

The old floating placement read child innerHeight immediately after asking
the host to enlarge its iframe from 192 to 460 px. A later child resize ran
the formula again. Bottom/top had already avoided this with fixed 42 px
edges (#117's predecessor player work), but floating still preferred above
and measured a changing viewport. The new synchronous string-only bridge
uses host-window space and compensates the player's inset when a frame must
extend upward. The menu is revealed only after its final local coordinates
are set; later resize calculations preserve the same screen-space anchor.
Host resize republishes even when the child's own size does not change.

Search and options now occupy separate flex areas, with only the choices
scrolling. Snapshot refresh preserves the list's scroll; a new search starts
at the top. Options is the native advanced-options.svg icon. The four skip
icons and English/Chinese titles come from the installed reader bundle's
20 px resources and reader.ftl. The commands reuse the existing navigation
operation and #117's paused explicit-return state push.

The floating header holds Options and Layout; its middle grip retains drag.
Options toggles only the three selection rows and changes height between
202 and 108 px. Each opening reads readAloud.openExpanded; later manual
changes stay local to that opening and survive layout changes. Shift+O and
playerOptions diagnostics choose the visible floating button before the
hidden native popup. Native expansion still uses its native selectors.

The default is top only when no layout user value exists. The shared resolver
checks PrefsBackend.has because Gecko can retain the old A default through
an in-place upgrade; explicit A/B/top choices survive. Speed controls and
keys use 0.5x steps, retaining existing limits/reset and remembered precision.
Automated regressions cover menu-side/bounds/inset stability, saved-layout
handling, Options routing, and all four navigation commands. Live geometry,
first-visible-frame behavior, search and actual button actions remain the
focused player-controls case's responsibility.

## A saved layout equal to the retained default is not a user value (2026-09-17 01:02, issue #118)

Gecko discarded the explicit A value because it equaled the retained A
default. The beta2 live check caught the missing user flag before menu tests;
reopening in the same session still showed A, but a new resolver read would
choose top. A focused regression reproduced that loss. The string default
branch is now corrected to top before saving a layout and at player startup;
existing user values remain intact. Beta3 reruns from baseline. The stopped
beta2 run restored its fixtures and named settings and does not count as
menu/control verification.
