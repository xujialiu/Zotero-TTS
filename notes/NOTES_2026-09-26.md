## Zotero's H and U annotate through two reader calls, and the segment must be the manager's own (2026-09-26 01:55, issue #145)

A reporter found H and U no longer annotating during playback with the
plugin on. The plugin now has keys of its own for it, Shift+H and
Shift+U, bindable like the rest. What they rest on, from Zotero
10.0.3-beta.3's `resource/reader/reader.js`:

- The bare keys live in the view's keydown (82110-82116), under
  `readAloudActive && !event.target.matches('button, select')`: a focus on
  any button — the plugin's Player included — swallows them before they
  are looked at. The annotate button of Zotero's hidden popup made the
  same call (38623-38628).
- The call is two steps: `_readAloudManager.getSegmentToAnnotate()` —
  the previous segment while under half and under 3 s into the current
  one (39386-39395; the Engine answers it from `session.ts`) — then
  `reader.addAnnotationFromReadAloudSegment(segment, type)` (84337). That
  one finds the segment by `this._readAloudManager.segments.indexOf`, so
  it must be the manager's own object: the Engine's controller holds the
  reader's segments waived (`controller.ts`), which unwrap to the same
  objects on the way back.
- The annotation is created at once (`_addAnnotationFromReadAloudSegments`),
  not on the popup's confirm; the popup is `readAloudState.annotationPopup`.
  A second call while it is open only retypes it
  (`setReadAloudAnnotationType`, 84553). A segment that already carries an
  annotation (`segmentAnnotations`) reopens that one's popup instead of
  adding another.

## Document voices are separate settings records, and native auto-activation needs a guard (2026-09-26 12:52, issue #146)

Zotero 10.0.3's reader bundle calls `activate()` at 83876 from
`_onReadAloudEngineStateChanged` whenever the popup is open, a voice is
selected, and the manager is inactive. `activate()` (82550) requests
segments; `_createController()` (82653) can also run after segments arrive
or a jump. A guard only on the Player's Play button would leave native
fallback speech possible. The memory adapter guards activation and
controller creation, and clears the unavailable fallback's selected ID so
native auto-activation cannot spin. The saved document voice stays intact.

The native `setReadAloudVoices()` (84332) updates the reader's state only;
it does not itself change an active manager. The adapter's session snapshot
therefore keeps a remote merge or settings default change out of ongoing
reading, while the next activation restores the latest document record.
The sandbox diagnostic `documentVoices()` exposes the default, records and
reader selections. Product and storage decisions are in design/ADR 0009.

A document key uses the personal-library namespace or a group ID plus the
attachment key. Local library IDs differ across machines; the EPUB
content-derived Document Id would collapse separate attachments. Records
are separate small preferences, enumerated into backups and merged one
at a time in the existing shared settings file. Manual intent outranks
inheritance before modification time is compared.

## Remaining time uses the audio clock, and sections share SDT refs with segments (2026-09-26 15:38, issue #148)

Static inspection of the installed Zotero 10.0.3 reader bundle found that
`SDTView._convertOutline` maps `structure.catalog.outline` entries to
`#sdt-` plus their dot-joined refs (`resource/reader/reader.js`,
80133–80146). Segments retain the same nested ref path in
`position.start`, followed by the text-node and character offsets
(71176–71248; the shared-position investigation of 2026-09-21 recorded the
coordinate shape). The feature reads the source outline directly from
`_internalReader._sdt.structure.catalog.outline`, caches boundaries by
outline and segment identity, and accepts only ordered starts that map to
segments without crossing an earlier sentence. A PDF page destination or
an EPUB spine item alone cannot establish that boundary.

`EngineSession.segmentEnd` resets the position when a run completes, and
clears its forward stop when a selection completes. A separate completion
flag preserves “Finished” through that reset; on the next Play, a cleared
forward stop also changes the estimate's label from selection to document.
The session computes clip remainder from the audio clock and includes the
actual outstanding gap. Pausing during a gap drops it, as the Engine
already did; the estimate must not retain silence that will never play.

The estimate's prefix sums are built lazily, and measured clip lengths
survive the 32-clip cache's eviction. Updating the visible minutes does not
walk the document or request audio. The initial language heuristic is a
rough prior; samples from the active voice refine it. It is independent of
word highlighting and produces no word timings. The product trade-off is
recorded in design/ADR 0010.

The owner requested local checks only and explicitly deferred
`zotero-tester` and all zotero-dev calls. Runtime compartment access,
chapter extraction on real documents, and layout geometry remain for the
later authorized live run. No live verification is claimed here.

Local verification passed: 159 test files / 2,748 tests with
`npm test -- --maxWorkers=2`, typecheck, build and documentation rendering.
One default-concurrency run exceeded the existing five-second startup test
limit; the reduced-concurrency run passed without changing that limit.
The built XPI is `1.15.2-beta4`, not installed. Feature changes remain
uncommitted until the owner's next command.

## Selected text supplies a start, not a reading limit (2026-09-26 17:24, issue #148)

The beta6 kit treated a consumed Shift+Space on selected text with
`scope: document` as a failure. Static inspection of Zotero 10.0.3 proves
that is the expected behavior: the only reader call to `setSegments`
(`resource/reader/reader.js` 84070) always supplies a null forward stop.
`_captureReadAloudStart` consumes the selection solely to find the starting
sentence; `startReadAloudAtPosition` (84239 onward) also starts there and
continues to document end. The plugin's smart Play preserves that behavior.

The earlier design interview discussed selection-only reading
conditionally but incorrectly assumed there was already such a UI path.
The time feature does not add one. Public wording now makes the selected
start explicit. The bounded-run estimate remains covered by core tests
and a controlled live manager contract check; it is not evidence of a
selection-only action in the Player. The tester is correcting this test
expectation without changing the installed production build.
