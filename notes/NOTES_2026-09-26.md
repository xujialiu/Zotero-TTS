## Zotero's H and U annotate through two reader calls, and the segment must be the manager's own (2026-09-26 01:55, issue #145)

A reporter found H and U no longer annotating during playback with the
plugin on. The plugin now has keys of its own for it, Shift+H and
Shift+U, bindable like the rest. What they rest on, from Zotero
10.0.3-beta.3's `resource/reader/reader.js`:

- The bare keys live in the view's keydown (82110-82116), under
  `readAloudActive && !event.target.matches('button, select')`: a focus on
  any button — the plugin's Player included — swallows them before they
  are looked at. The annotate button of Zotero's hidden popup made the
  same call (38623-38628).
- The call is two steps: `_readAloudManager.getSegmentToAnnotate()` —
  the previous segment while under half and under 3 s into the current
  one (39386-39395; the Engine answers it from `session.ts`) — then
  `reader.addAnnotationFromReadAloudSegment(segment, type)` (84337). That
  one finds the segment by `this._readAloudManager.segments.indexOf`, so
  it must be the manager's own object: the Engine's controller holds the
  reader's segments waived (`controller.ts`), which unwrap to the same
  objects on the way back.
- The annotation is created at once (`_addAnnotationFromReadAloudSegments`),
  not on the popup's confirm; the popup is `readAloudState.annotationPopup`.
  A second call while it is open only retypes it
  (`setReadAloudAnnotationType`, 84553). A segment that already carries an
  annotation (`segmentAnnotations`) reopens that one's popup instead of
  adding another.

## Document voices are separate settings records, and native auto-activation needs a guard (2026-09-26 12:52, issue #146)

Zotero 10.0.3's reader bundle calls `activate()` at 83876 from
`_onReadAloudEngineStateChanged` whenever the popup is open, a voice is
selected, and the manager is inactive. `activate()` (82550) requests
segments; `_createController()` (82653) can also run after segments arrive
or a jump. A guard only on the Player's Play button would leave native
fallback speech possible. The memory adapter guards activation and
controller creation, and clears the unavailable fallback's selected ID so
native auto-activation cannot spin. The saved document voice stays intact.

The native `setReadAloudVoices()` (84332) updates the reader's state only;
it does not itself change an active manager. The adapter's session snapshot
therefore keeps a remote merge or settings default change out of ongoing
reading, while the next activation restores the latest document record.
The sandbox diagnostic `documentVoices()` exposes the default, records and
reader selections. Product and storage decisions are in design/ADR 0009.

A document key uses the personal-library namespace or a group ID plus the
attachment key. Local library IDs differ across machines; the EPUB
content-derived Document Id would collapse separate attachments. Records
are separate small preferences, enumerated into backups and merged one
at a time in the existing shared settings file. Manual intent outranks
inheritance before modification time is compared.

## Fish Default was an unconditional catalog entry, independent of every source switch (2026-09-26 14:26, issue #147)

Fish Audio's catalog appended `mul/default` after merging official, own
and manual voices. It was never returned by Fish Official: the entry
selects synthesis without a `reference_id`. The connection probe also
uses it, independently of the selectable catalog. Fish Speech lists
server references and has no equivalent appended entry.

The eight source-combination tests reproduced the unconditional entry.
The catalog now gates it on `includeOwn`, including when the account has
no custom voices; disabled-source cache and outage tests cover its
absence with Your voices off. Its ID and synthesis path stay the same.
The document-voice unavailable guard from #146 already preserves saved
choices and blocks automatic substitution; no migration is needed.

## An open paused player can outlive its Engine session and reject listed voices (2026-09-26 15:49, issue #149)

Research through zotero-dev on macOS, Zotero 10.0.3-beta.3+80bc5565e,
installed Zotero-TTS 1.15.2-beta3: the existing manager was active and
paused, its selected voice null and controller absent, while its Engine
session was ended and still named the preceding Fish voice. It had 3,046
segments and 538 catalog entries, including 200 System entries. The
installed bundle hash was not captured; no build was installed.

Selecting listed Ava (Enhanced) reproduced `unavailable` twice. Albert,
Samantha and Ava then each displayed the exact message, "The voice list
is not ready. Open the player and try again." A temporary getter probe
saw Ava's valid ID during selection preview, then the original null
selection after restoration. The target was found. The handoff's
`begin` in `read-aloud/engine/voice-pick.ts` rejects an ended session
before preparing audio, and the notice maps that condition to a voice
list readiness message. Direct Ava synthesis through the sandbox
returned 183,726 bytes of WAV in 1,613 ms without a backend error.

This establishes the immediate failure from the existing state, not the
event that originally ended the session or cleared its voice. It does
not establish a macOS-only cause or a regression from #146. Zotero's
installed reader bundle selects a voice at 82347-82351 and applies it at
82507-82537; the plugin intercepts active selection before that committed
path. Further research must reproduce the initiating sequence separately.

The dedicated test WebDAV destination matched, pending writes settled,
and automatic sync/backup stayed suspended during checks. No fixture or
document playback was started. Temporary getter instrumentation was
removed. Snapshotted preferences, volume, WebDAV and sync switches matched
their original values and user-value flags after cleanup; document voice
records were unchanged. The host remained minimized. The issue holds the
reproduction and the subsequent behavior discussion; no fix was tested.

## Explicit selection rebuilds an ended session while paused (2026-09-26 16:03, issue #149)

The regression runs Zotero 10.0.3's verbatim manager fixture with the real
Engine, voice-pick and document-voice memory hooks. Destroying the
controller and flushing its cleanup leaves an active manager with an
ended session. Before the fix, all four recovery cases failed: paused,
stale-playing, same-voice re-selection, and a detached Engine. The first,
second and fourth kept a null selection; the same-voice shortcut rebuilt
without pausing. The latter needs the same recovery gate as a new voice.

The recovery now pauses before committing the explicit selection, attaches
a missing Engine, and lets the manager rebuild at its current segment.
It checks that an Engine controller was bound and removes a native
fallback if rebuilding failed. The ordinary selection hooks persist the
manual document choice. The successful path increments
`diagnostics.voiceSwitch().readers[i].handoff.recoveries`; live Handoffs
still use their existing path. Missing targets or segments remain refused.

The real-manager regressions retain segment index 2, keep the manager
paused in all four cases, issue no audio requests before Play, and request
the chosen voice on Play. Only the fixture document's record changes;
another record and the global default remain unchanged. A separate fault
injection proved a failed rebuild initially left a native controller, then
verified its removal. Existing tests cover ordinary playing and paused
Handoffs. The full suite passed 156 files / 2,742 tests with two workers
and a 30-second test timeout; typecheck passed.

The live checklist adds recovery item 13 to voice-switch. This is local
evidence only: the initiating event remains unknown, and live verification
awaits the owner's grant of Zotero access, currently assigned to another
agent. No Zotero connection or installation was made during implementation.
