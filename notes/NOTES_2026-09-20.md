## Gecko allows no copy out of a password field, revealed or not (2026-09-20 13:12, issue #19)

The pane's secret fields — the four API keys, the Cloudflare token, the
two Extra headers lines and the WebDAV password — were `type="password"`
since issue #19, uncovered by Gecko's own reveal button. The owner found
that the value it shows cannot be copied. It is not the reveal: Gecko
disables copy and cut on a password editor whatever its reveal state.
Measured in the running 10.0.3-beta.3 (Firefox 140, macOS) on the OpenAI
Compatible Extra headers field, 151 characters, all selected:

| field | `editor.canCopy()` | `editor.canCut()` |
|---|---|---|
| the secret as `type="password"` | `false` | `false` |
| a plain `type="text"` beside it (Model, 5 chars) | `true` | `true` |
| the same secret switched to `type="text"` | `true` | `true` |

Two more measurements settled the shape of the fix.

**The reveal button cannot be styled away** — as issue #19 already found
from the other side. A rule `#id::-moz-reveal { display: none !important }`
inserted into the preferences window from a chrome sheet does not merely
fail to apply: the whole rule is dropped at parse time, `style.sheet.cssRules`
coming back empty. So a password field always carries Gecko's eye, and a
control of the plugin's own beside it would be the second.

**`-webkit-text-security` is honored in this Gecko.**
`CSS.supports('-webkit-text-security', 'disc')` is true, and a `type="text"`
input with it renders the same dots a password field does — verified by
rendering three inputs into the main window and screenshotting them: a
masked value, a masked *empty* field, and an unmasked control. The empty
one still draws its placeholder in plain text, which is the constraint
issue #19 measured for the two Extra headers hints.

So the fields are ordinary text boxes, the cover is the pane's own, and
`ui/secret-rows.ts` inserts the eye that switches it. The stylesheet is
written the safe way round — `input.ztts-secret:not([data-revealed="true"])`
is covered — so markup alone, or a pane whose script never ran, still
covers the value. "Enabled means hidden" (issue #19) is no longer free
from Gecko's inert button on a `disabled` input: `provider-rows.ts`
covers the field and disables the eye when a section locks.

`diagnostics.secrets()` reports each field by the tail of its pref with
`type`, `textSecurity`, `revealed`, the eye's state and the value's
length; `secrets(true)` also selects each value for one reading of
`editor.canCopy()` and puts the selection and focus back.

## The screenshot bridge reaches the main window only (2026-09-20 13:14)

`zotero_screenshot` with `target: 'element'` resolves its selector against
the main Zotero window, and `target: 'window'` with the preferences
window's id from `zotero_list_windows` answers "Window not found with ID
41". A rendering check on the settings pane therefore renders its probe
into `navigator:browser` — same engine, same theme — or goes to the owner.
