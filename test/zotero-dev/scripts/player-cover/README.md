Before you start:

- WebDAV isolation (workflow "Test WebDAV first") runs once per session, outside this kit, before installing — snapshot `webdav.*`, suspend the three sync switches, point `webdav.url` at the test folder, and restore all four (url last of that group) only after this kit's `90-cleanup.js` has erased the fixtures.
- Install the xpi, confirm `-betaN`, run `diagnostics.startup()`, then `01-baseline.js`. Fixtures are `fixture-a.pdf` (17 segments, 2 pages) and `return-key/return-key.epub` (241 segments); the EPUB opens in `paginated` flow by default here.
- Window: this whole case is geometry-driven, so the host stays restored/maximized for the run; `01-baseline.js` only minimizes for its own bridge-only pref snapshot, and `90-cleanup.js`'s caller minimizes again at the very end (this case's owner-set exception to leaving window state as found) after confirming the original bounds were reproducible (`.maximize()`, not `.restore()`, when the baseline's `windowState` was 1 — `.restore()` left a smaller, differently-positioned "normal" window here).
- Trusted wheel scrolls (`10-item4-keep-following.js`) target the reader's own top-level window (`reader._window`, the main Zotero window) at `<browser>`-relative coordinates; the `<browser>` element carrying the selected reader tab was found at `top:37,left:0` on this window (three stacked `<browser>` elements share that rect; `browser[selected="true"]` was not reliable — see Limits) and a 120 `deltaY` moved the PDF viewer 60px.
- `readAloud.memory` is overridden with a listed Fish voice (`fish::en/933563129e564b19a115bedd57b7406a`) before any player opens (issue #133's stale `local::af_fake`) and restored byte-for-byte last of every pref.

Limits:

- `06-item2-split-view.js`: Zotero's own secondary-view find popup did not open live here even once the secondary PDF view's own iframe was confirmed mounted and connected (`ir._state.secondaryViewFindState.popupOpen` stayed `false` after `toggleFindPopup({primary:false,open:true})`, no thrown error). The secondary side of the case's claim is evidenced by a synthetic `.find-popup`-classed probe element appended as a real child of the live `.secondary-view` node (CSS matches it identically to a real one), cross-checked against the primary view's own synthetic-vs-real agreement first.
- `08-item4-covered.js`: PDF's `covered` (sentence-in-view.ts) is `null`, not `{0,0}`, once a session fully closes, because it is computed only when an active segment exists; EPUB's (dom-follow.ts) is not gated the same way and does read `{0,0}`. Both are reported as their own value rather than forced to agree; this is a source-level asymmetry between the two follow modules, not a defect from this fix.
- `09-item4-outside-mode.js`: the trigger that actually moves a clipped sentence is the placement scroll's own native `scroll` event (both follows evaluate on it), not an explicit resume or `_stateChanged()` — measured PAUSED throughout. A resume onto the SAME still-active segment, and a repeat placement scroll landing back on an already-decided value, were both observed to produce no NEW decision; read as the manual-tracker's own 180ms-debounced de-dupe (manual-follow.ts), not as "resuming does nothing" in general. `sawCut` was `null` for the PDF/top round even though the correction demonstrably completed (`landedOk:true`) — the decision was already recorded by the first "before" read, before this run's own polling loop started (confirmed by an isolated repeat with earlier polling).
- `08-am-center-and-reload.js`-style mask sampling (player-controls kit) was reused for `04-item1-epub.js`'s probe; its `blurRadiusPx()` helper is new here (see the Limits entry above).
- A run-scoped `readAloud.autoScrollMode` reverted correctly at `09-item4-outside-mode.js`'s own cleanup and was independently re-verified stable 5s later; one attempt earlier in this run needed a manual re-clear when it read back `outside` immediately after that same cleanup line ran (cause not identified — no observer or debounced writer for this pref was found; flagged here for a future run to watch for, not reproduced on retry).
- Trusted-wheel calibration is specific to this window's size (1458×949 outer, browser rect 1458×912): a `deltaY` of 120 moved the PDF viewer's `viewerContainer` 60px here; a different window size will need recalibrating.
