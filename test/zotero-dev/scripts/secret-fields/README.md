## Before you start

- Build: `zotero_plugin_list` + `diagnostics.startup()` first (done directly, per the tester workflow, not a script here); confirm the profile's installed xpi bytes against the built one (`shasum -a 256`) — this profile has run another session's build before.
- `00` opens no fixture and imports nothing: the case is settings-pane-only. It does record the owner's open reader sessions and does **not** close them — none of this case's providers affect a `fish::` session (confirmed live with `diagnostics.readingImpact` before writing `04`).
- `01` opens the settings window itself (closing one already open first, since a reinstalled pane keeps the old markup) and leaves it open for `02`–`05`; run them in order after it.
- State touched: `local.enabled` is flipped on and back off by `04` (a real Enable click, free — Local has no synthesis probe and its configured server answered in 268 ms); the reveal state of whichever field a script clicks (never persisted — every pane opens masked, so there is nothing to restore there beyond leaving it covered, which `04` and `90` both do). No field's value is ever written or printed — only `length`.
- `90` must run last; it reads `state.baseline` from `00`.

## Limits

- **The brief's offered cheap route does not work**: writing `local.enabled` straight to `true` with `Services.prefs.setBoolPref` — no button pressed — leaves the field exactly as it was (still revealed, eye still enabled); writing it back to `false` does the same nothing. Read from source (`src/ui/provider-rows.ts`): `paint()`, which is what calls `setSecretLocked`, only ever runs at pane construction, inside the Enable/Disable/Test click handlers themselves, and from a settings-restore's `onRestored`. No `Zotero.Prefs.registerObserver` exists for a provider's `.enabled` name, so nothing else repaints the lock while the pane stays open. `04` tries the raw write first and falls back to a real click only if it does not move the field — confirmed this run — and restores `local.enabled` in a `finally` either way.
- **Host minimize is not synchronous**: `00`'s `host.minimize()` read back `windowState: 3` (not yet 2) in the same script; by `90`, seconds later, it read 2. Matches the reading-guard kit's own note ("the bridge minimize no-op"). Harmless here — every check in this case drives the settings window, a separate top-level window that renders regardless of the main browser window's state.
- **`zotero_screenshot`**: `target: "window"` with the preferences window's id (from `zotero_list_windows`) worked cleanly this run (a real PNG of the pane, WebDAV section, dark theme) — the brief's own "Window not found" earlier the same day did not reproduce; `target: "element"` resolves only against the **main** Zotero window whatever selector is given (confirmed: `#ztts-provider-cloudflare button.ztts-reveal` "Element not found", `#zotero-pane` succeeded and returned the library pane, not the settings window) — for an element inside the settings window, `05`'s `drawSnapshot` route is what actually reaches it.
- **A field's `placeholder` attribute is unaffected by masking** but nothing in this profile is currently an *empty* Extra headers field to show it live — `fishspeech.headers`, `local.headers` and `compatible.headers` all already hold 151 characters. `05` confirms the attribute is correctly set (`"Name: value; Name: value"`) on `local.headers` regardless; whether it visibly paints behind the mask when the field is empty was not exercised live, to avoid clearing a real configured value.
- **Not this case's finding**: `can't access property "length", list is undefined` at `zotero-tts.js:0:74` (no stack; `list.length` appears 12 times in the built bundle, not narrowed further) logged three times this session — once during `04`'s real Enable click (`onVoicesChanged` → the voice browser reloading), twice during the `01`/`05`/`90` recheck's pane reopen — and once more *before* this session's testing began (12:35 PM, an earlier install). Pre-existing, not unique to this build, and outside this case's scope; reported for the record, not chased further here.
